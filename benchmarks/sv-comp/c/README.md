# C versions of the local SV-COMP benchmarks

The 481 tasks in this folder are C programs with the property `unreach-call`,
all expected true, for comparing Cuvée with other verifiers on the same
programs, e.g. with BenchExec on the task set `C.unreach-call.Unbounded` of
`xml/*.xml`. The 165 tasks expected false were removed (October 12, 2026).

## Origin

- The tasks are those of the SV-COMP categories ReachSafety-Loops and
  ReachSafety-Arrays (`sv-benchmarks/c/<folder>`), translated by hand to Dafny
  in [../dafny](../dafny) (see [../dafny/summary.md](../dafny/summary.md)),
  where concrete loop bounds are replaced by symbolic ones, hence unbounded.
- Each C program is printed from its Dafny translation by
  `./Cuvee.sh -print c -known dfy,teq,rw <task>.dfy`, as its first lines
  state. Its task definition `<task>.yml` has the expected verdict of the
  original task (generated by `scripts/c_tasks.py`, which is not part of the
  repository), and [c.set](c.set) includes them all by a wildcard.
- [expected.csv](expected.csv) records the results of Cuvée on them
  (`./Cuvee.sh -record`). It was recorded before the patches below, and the
  expected verdicts of the `.yml` files are unchanged.

## Patches

The printed programs are not valid input for other verifiers. Four
scripts patch them in place, in this order. All of them apply to all `*/*.c` below this
folder (or the folder given as argument), and leave files alone that are
patched already.

```
python3 benchmarks/sv-comp/c/harness.py
python3 benchmarks/sv-comp/c/arrays.py          # --dry only reports
python3 benchmarks/sv-comp/c/nondet.py
python3 benchmarks/sv-comp/c/sizes.py
```

1. [harness.py](harness.py) adds the SV-COMP harness after the leading
   comments: `reach_error` (with the file's name and line, as in
   sv-benchmarks), the declarations of the `__VERIFIER_nondet_*` functions
   used, `assume_abort_if_not`, and `__VERIFIER_assert`, which calls
   `reach_error`. In the code, `assert(...)` becomes `__VERIFIER_assert(...)`
   and `__VERIFIER_assume(...)` becomes `assume_abort_if_not(...)`. Without
   it, no program calls `reach_error`, so that all tasks would trivially be
   safe for other verifiers. `true` and `false` become `1` and `0`, which C
   has only with `stdbool.h`; nothing is included. `loops-crafted-1/watermelon`
   declares them as global variables (`int true;`, initialized by
   `true = true;`, hence 0), which are dropped.
2. [arrays.py](arrays.py) sizes the local arrays declared without a size
   (`int a[];`, `int A[][];`, not valid C) by an unbounded size `N`, which the
   program assumes to be nonnegative (`assume_abort_if_not(0 <= N)`), per
   function; arrays of several dimensions get `N` for each:
   - with the function's own `N`, assigned at the top level or declared but
     not assigned (an arbitrary value, as before), the declarations move right
     after the assignment or the other declarations; if loops over the arrays
     go beyond `N` (up to `2 * N`, `i <= N`, or constants), the arrays get a
     fresh size `M` instead, assumed to cover these bounds, and `N` is left
     alone (`array_doub_access_init_const`, `array_tripl_access_init_const`,
     `vogal-2`); the size covers the accesses at an offset of the loop variable
     too, e.g. `2 * N + 1 < M` for `a[2 * i + 1]` with `i <= N` (since Oct 14,
     2026, when TriCera, which checks memory safety, found the two `array-cav19`
     tasks unsafe; both patched by hand);
   - without `N`, a fresh `int N = __VERIFIER_nondet_int()`, with the
     declarations right before the first top-level statement that uses an
     array, assumed to cover the program's own bounds there: those of the
     loops over the arrays (`SIZE <= N` for `while (i < SIZE ...)`), of direct
     accesses (`a[SIZE / 2]`, `SIZE / 2 < N`), and the other arguments of
     calls that pass an array (`linear_search(a, SIZE, 3)`, `SIZE <= N`), if
     their variables do not change afterwards; loops that end at a sentinel
     have no bound;
   - with a parameter `N`, at the start of the function.

   Without the bounds, the fresh `N` could be smaller than the program's own
   bound, and the accesses beyond it, undefined in C, make `reach_error`
   reachable in the compiled program (as Korn's fuzzer found).
3. [nondet.py](nondet.py) initializes the local variables declared without
   a value (`int x;`, `_Bool b;`), whose reads are undefined in C, by
   `__VERIFIER_nondet_int()` and `__VERIFIER_nondet_bool()`, as they are
   arbitrary in the Dafny translations. Globals stay zero, as the
   translations require (`requires SIZE == 0`). It runs after arrays.py,
   which looks for `N` declared without a value.
4. [sizes.py](sizes.py) bounds the sizes `N` and `M` of arrays.py from
   above, such that the arrays of a function together take less than 2^31
   bytes, the largest object in ILP32: by the largest limit of a datatype
   2^k - 1 below, e.g. `N <= 536870911` (2^29 - 1) for one `int` array,
   `N <= 16383` (2^14 - 1) for one `int A[N][N]`. Without, the arrays wrap
   around the address space and overlap, which other verifiers report as
   reachable errors.

Before nondet.py and sizes.py, other verifiers found 72 tasks false whose
expected verdict is true, mostly because the concrete bounds of the originals
are needed after all: see [false-verdicts.md](false-verdicts.md). Besides
sizes.py, 15 of these tasks are patched by hand with conditions on their
inputs under which the property holds, e.g. `N % 4 == 0`
(`assume_abort_if_not(...)`, see the section "Fixes" there), which their
Dafny translations assume as well.

The tasks are meant for verifiers that treat the arithmetic of C as
unbounded: the bounds that kept the arithmetic of 19 other tasks within
`int` were removed again (2026-10-12), so that these tasks are false for
verifiers with machine integers but true with mathematical ones, as their
Dafny translations. The other 9, false only for AISE, are unchanged.

Printing the programs again from the Dafny translations undoes the patches;
their diff is in [../dafny/c_patches.diff](../dafny/c_patches.diff), for
changing the translations accordingly.

Five tasks were removed (2026-10-12):
`array-examples/data_structures_set_multi_proc_ground-1`, `-2`,
`data_structures_set_multi_proc_trivial_ground`, `sanfoundry_43_ground`, and
`array-industry-pattern/check_removal_from_set_after_insertion`. Their C
programs pass an array to a function that changes it, which needs the array
as a global variable in Dafny, where arrays are values, and C has no global
arrays of symbolic size.
