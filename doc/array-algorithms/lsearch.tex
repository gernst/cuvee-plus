\section{Linear Search: a Constraint Named and Instantiated}\label{sec:lsearch}

\subsection{The program}
\begin{lstlisting}
method lsearch(a: array<int, int>, n: int, x: int) returns (i: int)
  requires 0 <= n
  ensures 0 <= i <= n
  ensures i < n ==> a[i] == x
  ensures forall k: int :: 0 <= k < i ==> a[k] != x
{
  i := 0;
  while i < n && a[i] != x { i := i + 1; }
}
\end{lstlisting}
The first index of $x$ among $a[0..n)$, or $n$. The test reads the array, so the number of iterations is not
determined by $n$.

\subsection{The system}
\begin{gather}
  K = \cnt(0, 1, n') \qquad I = \tr{0}{\bl{K}}{i, k \mapsto i + 1} \qquad i = \cur(I) \label{eq:ls0}\\
  \al{\bl{K}, \bl{I}}{k, i \mapsto i < n \wedge a[i] \ne x} \label{eq:ls1}\\
  \neg(i < n \wedge a[i] \ne x) \label{eq:ls2}
\end{gather}
The run is \texttt{-teq -split -prove}: the postcondition is split into one goal per conjunct, the quantified
one as $0 \le k < i \wedge a[k] = x \Rightarrow \mathsf{false}$.

\subsection{What the proof needs}
\emph{From the database, the counter.} $I$ is a counter by \lemma{counter\_def}, so $i = \intf(n')$ by
\lemma{current\_counter}. Inside the constraint the value of $i$ in iteration $k$ is $k$
(\lemma{earlier\_counter}), and the constraint splits into $\al{\bl{\cnt(0, 1, n')}}{k \mapsto k < n}$, which
\lemma{invs\_counter\_upper\_nonnegative} turns into $\intf(n') \le n$ for $0 \le n$, and the search
constraint $\al{\bl{\cnt(0, 1, n')}}{k \mapsto a[k] \ne x}$. The first two postconditions follow, and the third
from the exit \eqref{eq:ls2}.

\emph{For the last postcondition, the constraint at a position.} The goal needs $a[k] \ne x$ for a $k$ below
$i$, which is the search constraint at position $k$. A rule cannot take the constraint itself as a side
condition and instantiate it: matching an iteration constraint as a condition builds the context of its
combinator, in which the reads it contains are rewritten, and a rule general enough to match there recurs
(Section~\ref{sec:principles:termination}). Instead, one lemma names what the constraint says, and a second one
uses the name:
\begin{align*}
  &\lemma{not\_occurs\_selects\_def}:\\
  &\quad \al{\bl{\cnt(i, 1, n)}}{k \mapsto a[k] \ne x}\ \Longleftrightarrow\ \neg\mathsf{occurs}(x, \mathsf{selects}(a, \bl{\cnt(i, 1, n)}))\\[2pt]
  &\lemma{select\_not\_occurs\_selects}:\\
  &\quad \neg\mathsf{occurs}(x, \mathsf{selects}(a, \bl{\cnt(i, 1, n)}))\ \wedge\ i \le k < i + \intf(n)
    \ \Longrightarrow\ (a[k] = x) \Longleftrightarrow \mathsf{false}
\end{align*}
The first replaces the constraint by the atom ``$x$ does not occur among the values of $a$ at
$0, \ldots, n' - 1$''. The second is a rule on the atom $a[k] = x$ of the goal: its first condition is matched
against the atom just produced, which binds $i := 0$ and $n := n'$; its bounds are closed and decided by the
arithmetic from $0 \le k < i$ and $i = \intf(n')$. The hypothesis $a[k] = x$ becomes $\mathsf{false}$.

The same pair is in the module for searching, there with the second lemma as a forward fact
(Section~\ref{sec:engine:forward}): triggered by the read $a[k]$, it assumes $a[k] \ne x$ wherever the read
occurs, rather than rewriting one particular atom. The pattern is general: an iteration constraint becomes a
named fact about the prefix that the loop visited, and a second lemma uses the fact at any position in the
prefix.
